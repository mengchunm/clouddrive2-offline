# 1.5.35 发布说明

此版本修复 Native Host v3 注册正确但仍没有进入持久消息循环的问题。

## 问题原因

v3 让注册表指向用户实际运行的安装 CMD。Chrome 在当前环境启动批处理 Native Host 时传入了空参数，而安装 CMD 使用“是否存在第一个参数”区分浏览器调用和用户双击。因此 Chrome 调用被误判为安装流程，最终停在交互式 `pause`，没有启动 Native Messaging 消息循环。

## 修复方式

- 用户运行的 `clouddrive2-native-host-v4.cmd` 只负责安装。
- 安装时生成 `clouddrive2-native-host-run.cmd` 作为专用浏览器入口。
- Host 清单和 Chrome/Edge 注册表最终指向专用入口。
- 专用入口无条件以 `-NativeHost` 启动 PowerShell，不读取 Chrome 参数，不包含安装、提示或暂停逻辑。
- Host 协议升级为 v4，设置页要求 `ping.protocol >= 4`。

## 正确安装后的判定

- Host 清单的 `path` 以 `clouddrive2-native-host-run.cmd` 结尾。
- `clouddrive2-native-host.ps1` 包含协议版本 4 和持久 `while` 消息循环。
- 本地目录功能启用时存在一个由浏览器启动的 PowerShell Native Host 进程。

旧 EXE、旧 CMD、v2 CMD 和 v3 CMD 可以继续留在下载目录，只要注册表不再指向它们就不会生效。
