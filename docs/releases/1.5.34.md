# 1.5.34 发布说明

此版本修复 Native Host v2 安装后仍实际运行旧助手的问题。

## 问题原因

v2 安装脚本虽然以 `clouddrive2-native-host-v2.cmd` 下载，但 PowerShell 安装逻辑把 Host 路径固定写成同目录下的 `clouddrive2-native-host.cmd`。如果旧文件仍然存在，Chrome 和 Edge 会继续启动旧版，并由旧 CMD 再次覆盖已经解出的 PowerShell 脚本。

因此，仅看到 v2 文件已经下载或运行，并不能证明 v2 已经生效。

## 修复

- CMD 通过环境变量把自身真实绝对路径传给 PowerShell。
- Native Messaging Host 清单写入用户实际运行的 CMD 路径。
- 协议版本升级为 v3。
- 下载文件改为 `clouddrive2-native-host-v3.cmd`，不复用有缺陷的 v2 文件。
- 设置页要求 `ping.protocol >= 3`，否则明确判定为旧助手。

## 升级步骤

1. 重新加载 1.5.34 扩展。
2. 刷新 CloudDrive2 网页。
3. 打开扩展设置并启用本地目录功能。
4. 运行新下载的 `clouddrive2-native-host-v3.cmd`。
5. 等待设置页确认启用。

旧 CMD、v2 CMD 或早期 EXE 即使仍留在下载目录也不会生效；以 Chrome/Edge 注册表中 Host 清单的 `path` 为准。
